# DTM ETL — 內政部 20 m DTM → EPSG:3826 裁切 GeoTIFF

RFC 模組 1、D2(ETL 統一 EPSG:3826)。本階段的產物是 **中間格式**:D3 道路高程觀測(FTP-32)與 D9 地形/heightfield(FTP-34)都從這裡取地表高。

## 單一指令

```bash
python -m scene_pipeline.etl.dtm \
  --source /path/to/dtm_20m.tif \
  --out build/dtm/dtm_20m_epsg3826.tif \
  --source-meta config/nlsc_dtm20m.json
```

`--source` 可以是本機檔案,也可以是 `http(s)` URL(會先下載)。輸出兩個檔:

| 檔案 | 內容 |
| --- | --- |
| `<out>.tif` | 裁切後的 EPSG:3826 GeoTIFF,float32,deflate 壓縮,tiled |
| `<out 同 stem>.source.json` | 來源與版次紀錄 |

完整旗標見 `--help`。常用的幾個:`--area`(預設 `contracts/constants/m1_area.json`)、`--resolution`(預設 20)、`--resampling`(預設 bilinear)、`--source-nodata`(可重複)。

## 像元對齊規則(AC2)

三條,合起來保證「輸出必覆蓋 bbox,且 tile 邊界落在像元邊上」:

1. **格網錨定於 EPSG:3826 原點 (0, 0)**。每個像元的**邊**都落在解析度的整數倍上。請求的 bbox **不會**改變格網相位 —— 換句話說,同一份 DTM 用不同 bbox 裁兩次,重疊區的像元完全對得起來,可以直接相減。
2. **bbox 向外貼齊**:min 側 `floor`、max 側 `ceil`。輸出因此**恆涵蓋**請求範圍。這裡不用四捨五入:round 平均而言會讓輸出比 bbox 小,等於默默從 M1 認定自己擁有的範圍邊緣削掉一條。
3. **貼齊是最小的**:任一邊最多只加一個像元。

`check_tile_alignment` 會硬性檢查解析度能整除 `contracts/constants/grid.json` 的 `tile_size_m`。這不是形式檢查:`contracts/spec/grid.md` 之所以選 500 m tile,部分理由就是「每邊 25 格 20 m DTM,地形頂點可與 tile 邊界對齊」,而該性質只有在兩個格網同相位時才成立。20 m 不整除 tile 時本工具直接拒跑,不會產生一份看似正常、接縫卻對不齊的地形。

M1 bbox 四界皆為 20 的整數倍,故輸出恰為 **175 × 175** 像元、範圍等於 bbox 本身。

另有一道 `MAX_OUTPUT_PIXELS`(1e8 像元)上限:bbox 誤填成經緯度或整個臺灣時,應該在一句話內失敗,而不是吃光記憶體之後才失敗。

## nodata 策略(AC3)

策略代號 `no-fill-no-contaminate/v1`,寫入紀錄檔的 `nodata.policy`。輸出 nodata 常數為 **-9999.0**(遠離任何合理的 TWVD2001 正高,不會和真實地表撞值)。

**N1 — 不填補。** 本階段不做任何內插、補洞或外插。空洞原樣保留。補洞是下游 D9 的決定:那裡才知道路廊在哪、才知道該用什麼假設補。在這裡補,等於把一個猜測洗成「量測到的地表」寫進每個後續階段都當成事實的中間產物。

**N2 — 不污染。** 一個輸出像元只有在其重取樣核內**所有**來源像元都有效時才有效。實作方式:用同一個核重取樣一張 1/0 有效性遮罩,得到的值就是該像元核內有效權重的比例,要求它等於 1.0。

N2 看起來像多餘的保險,實際不是。**GDAL 自帶的 `src_nodata` 處理會跨洞外插**:它把核內存活的鄰居重新正規化,產出一個沒有任何標記的數字。實測(合成平面、挖掉 1 像元、輸出格網偏移半像元):

| 位置 | 平面真值 | GDAL `src_nodata` 產出 |
| --- | --- | --- |
| 洞的鄰接像元 | 12 / 16 / 18 | 10.667 / 17.333 / 18.667 |

對一份要餵給 D3 道路高程與 D8 physics 的 DTM,這是最不該發生的事:**看得見的洞遠比看不見的錯高程安全**。因此本工具自行實作遮罩,寧可讓洞比原本大一圈(邊緣像元被核觸及即作廢),也不輸出來歷不明的高程。

**N3 — sentinel 一律轉為輸出 nodata。** 被視為空洞的值有三種來源:NaN(永遠算空洞)、來源檔自己宣告的 nodata tag、以及 `--source-nodata` 明確宣告的值。三者都會寫進紀錄檔的 `nodata.source_nodata`。

**未宣告的 sentinel 不會被猜。** 沒有 tag、也沒有 `--source-nodata` 時,-999 就是資料而不是空洞。自作聰明地把負值當成空洞,會默默刪掉真實的負高程。ASCII grid 形式的 DTM 常常不帶 tag,這時請明確加 `--source-nodata -999`。

**N4 — 空的東西一律報錯,不靜默產出。** 來源範圍與 bbox 完全不相交(拿錯圖幅)、或套用策略後一個有效像元都不剩,都是明確錯誤。

部分覆蓋則**不是**錯誤:輸出範圍仍然是完整的 bbox,缺的部分是 nodata,實際有效比例記在紀錄檔的 `valid_fraction`。輸出不會為了遷就資料而縮小 —— 縮小就等於把「資料缺了」偽裝成「範圍本來就這麼大」。

## 重取樣

預設 `bilinear`。來源若已是 EPSG:3826、同解析度、同相位(M1 的實際情形),bilinear 重取樣**位元精確**(實測 max abs diff = 0.0),因此不需要另開一條 windowed-read 路徑,單一程式路徑即可保證對齊來源的值不被動到。

## 來源與版次紀錄(AC4)

PRD §4 要求成品標示來源。這裡是**機械強制**的:`name` / `url` / `license` / `retrieved` 四個欄位缺一個,就不會有輸出檔 —— 而且在下載開始前就先擋掉,不會白花一次下載。

值從 `--source-meta` JSON 檔或個別旗標來(旗標優先)。`retrieved` 只有在**本次執行親自下載**時才會自動填入當日 UTC 日期;對本機既有檔案必須由操作者提供,因為沒有人見證過那個檔案是什麼時候拿到的,自動填「今天」是偽造來源日期。

**本模組刻意不內建 NLSC dataset id 與 URL 的 registry。** 那些值會是我對 data.gov.tw 頁面的印象而非查證過的事實,把一組可能錯誤的授權字串放在看起來像官方常數的地方,比沒有常數更糟。請從實際下載的頁面抄一次到 `--source-meta` 檔,之後重複沿用。

紀錄檔內容除了四個屬名欄位,還包含:來源檔 sha256(釘住實際讀到的位元組)、來源 CRS / 解析度 / 範圍、輸出格網參數與對齊規則、重取樣方式、nodata 策略與 sentinel 清單、`valid_fraction`、工具名稱與版本、產生時間。

## 發佈與失敗狀態

兩個檔都先寫成暫存檔再 `os.replace` 移入,紀錄檔先移、GeoTIFF 後移。守的是這個情況:半寫入的 GeoTIFF 留在正式路徑上,下游打開時會看到一個完全正常的檔頭配上截斷的高程。

保證:**成功產出的 GeoTIFF 一定有紀錄檔;失敗的執行不會留下 GeoTIFF,也不留暫存檔。** GeoTIFF 是正本;若在最後一步失敗而留下較新的 `.source.json`,重跑會一併覆寫,且沒有任何下游只讀紀錄檔。

## 已知限制

- 只讀第 1 個 band。多 band 的 DTM 不在 M1 範圍內。
- 高程值原樣通過,不做 geoid 轉換。`contracts/spec/grid.md` 的 v0.1 將 `geoid_offset_m` 定為 0.0 且明講尚未實測,故此處不代為假設。
- 壓縮檔(.zip)不會自動解開;`--source` 需指向 rasterio 能直接開的檔案。
